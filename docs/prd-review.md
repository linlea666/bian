# 对《Binance 合约跟单智能风控系统 PRD v1.0》的评审

总体：方向正确、边界清楚（不承诺自动改原生跟单仓位、提醒中不得写“已止损”、数据质量分级、规则去重和升级、样本外验证），这些都已按 PRD 实现。下面是需要修正或补充的地方。

## 1. 数据来源比 PRD 估计的好，不需要 CSV 导入

PRD 假设领航员历史只能靠用户导出 CSV。实测发现公开接口能直接拿到领航员**完整的已平仓历史**（开平时间、均价、杠杆、ROI），配合公开 K 线就能近似重建 MAE/MFE。所以 M0/M1 可以一步到位，FR-01 的 CSV 导入降级为“可选”。

## 2. 持仓实时性分两种情况

- 领航员开启“展示持仓”：公开接口能直接轮询。
- 未开启：只能用登录凭证读取“我的跟单仓位”，这样拿到的是**我真实的仓位**（含强平价），比领航员仓位更适合做风控。PRD 里的“人工同步仓位”基本可以不用。

## 3. 用 ROI 设止损必须按领航员杠杆分别看

同样是 -30% ROI，5x 杠杆约等于价格反向 6%，75x 只有 0.4%，容易被正常波动打掉。PRD 的默认值（-20/-35/+20/15 点）只能当起点，应该先用 `bian backtest` 为每个领航员单独选参数，并支持按领航员覆盖配置（已实现）。

## 4. 实测：硬止损不一定能“少亏”

对一位 286 笔样本的领航员回测（见 `docs/examples/backtest-leader-a.md`）：

- 原始跟单累计 +105.7 份保证金，最大回撤 13.6。
- 加任何一档硬止损后，收益都掉到 +7 以下：它的利润主要来自少数暴利单，以及先浮亏后扛回来的单子，止损会把这些砍掉（-10% 止损误杀了 89 笔盈利单）。
- 保本类规则把回撤降到 8.5 左右，但也少赚了约 60%。样本外检验中，没有任何规则胜过原始跟单。

结论：要做到“亏时少亏、赚时跟上”，**选领航员和控制仓位比加止损更有效**。PRD 应把“领航员筛选/淘汰”提到 P0，止损规则则按领航员单独验证后再用。

## 5. 币安跟单 TP/SL 的限制要体现在提醒里

PRD 3.1 提到跟单 TP/SL 只对设置后的新仓生效，加仓后不会重算。所以检测到加仓（R07）时要提醒你复查止损（已实现）。

## 6. 凭证安全

`p20t` 是网页登录会话，泄露等于账号被登录（虽然不能提现，但能操作交易）。只放在环境变量里，不写入文件，不打日志；过期（通常 7–30 天）时紧急提醒（已实现）。不要把它交给任何第三方服务。

## 7. 简化的地方

- 存储用 SQLite，不用 PostgreSQL / 时序库 / 对象存储；个人使用足够，部署简单。
- 前端 Dashboard 暂不做，先用 CLI + Telegram。有需要再加。
- P2 自动执行不做（用户已选择保留原生跟单 + 人工操作）。
